# shopbot

Telegram-бот выдачи доступа поверх панели 3x-ui. Оплата принимается вручную:
бот выставляет счёт с уникальной суммой, владелец подтверждает поступление
кнопкой, бот создаёт или продлевает клиента в панели и присылает ссылку
подписки.

## Что он делает

| Покупатель | Владелец |
|---|---|
| `/start` — меню | `/orders` — заказы на проверке |
| «Тарифы» — выбор и счёт | Кнопки «Подтвердить» / «Отклонить» под каждым заказом |
| «Я оплатил» — заказ уходит на проверку | Уведомление о каждом новом заказе |
| «Моя подписка» — срок, трафик, ссылка | |

Пробный период выдаётся автоматически, один раз на Telegram-аккаунт.

## Установка

Ставится **на тот же сервер, что и панель**: токен области `admin` даёт полный
контроль над панелью, и по сети он ходить не должен.

```bash
apt install -y python3-venv
mkdir -p /opt/shopbot /var/lib/shopbot
# скопировать каталог shopbot/ в /opt/shopbot
cd /opt/shopbot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp .env.example .env
chmod 600 .env
nano .env          # заполнить
```

В `.env` два секрета — токен бота и токен панели. Файл обязан быть `600`,
и его содержимое не должно попадать ни в логи, ни в бэкапы в облако.

### Токен панели

Панель → **Настройки → API токены** → создать с областью `admin`.

### Номера входящих

`bot/tariffs.py`, константа `STANDARD_INBOUNDS`. Номера смотреть в панели,
раздел «Входящие», столбец ID. Пока там заглушка `(1, 2, 3, 4, 5)`.

## Проверка до запуска в бой

```bash
cd /opt/shopbot
.venv/bin/python -m compileall -q bot     # синтаксис
.venv/bin/python -m bot.main              # запуск в терминале
```

Первым делом выдать себе пробный период и убедиться, что клиент появился
в панели с правильным набором входящих и сроком. Потом оформить платный
заказ на себя и провести его через подтверждение.

## systemd

`/etc/systemd/system/shopbot.service`:

```ini
[Unit]
Description=VPN shop bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/shopbot
ExecStart=/opt/shopbot/.venv/bin/python -m bot.main
Restart=always
RestartSec=10
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/shopbot

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now shopbot
journalctl -u shopbot -f
```

## Устройство

```
handlers/user.py   — покупатель: тарифы, заказ, статус
handlers/admin.py  — владелец: подтверждение, отклонение
service.py         — выдача и продление, расчёт срока
panel.py           — HTTP-клиент панели  ← единственное место, зависящее от версии
db.py              — заказы, переходы статусов
tariffs.py         — цены и наборы входящих
texts.py           — формулировки
```

### Про деньги и двойные нажатия

Статус заказа меняется только через `UPDATE ... WHERE status=?`. Второе
нажатие «Подтвердить» не проходит условие и ничего не делает. Если панель
отказала уже после смены статуса, заказ возвращается в очередь — кнопка
остаётся рабочей, деньги не теряются.

Копейки в сумме — это номер заказа. Они занимаются только живыми заказами
и переиспользуются, поэтому предел — 100 одновременных неоплаченных заказов
на один тариф.

### Продление

Срок прибавляется к остатку, а не обнуляет его. `subId` не меняется, то есть
ссылка подписки у покупателя остаётся прежней и приложение настраивать заново
не нужно.
